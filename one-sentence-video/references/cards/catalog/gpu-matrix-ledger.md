## 意图
把「枯燥的算力吞吐、并行策略（EP/DP）、缓存命中率与单位成本账本（如单卡每小时 $38 vs 实际成本 $5.7、木桶效应最慢卡阻塞）」转化为一眼可数的 GPU 砖块矩阵染色波浪与巨型倍率算式，让硬核系统经济学产生强烈的视觉爽感。

## 适用
- 大模型推理/训练成本核算、GPU 集群并行效率（EP/DP/TP）、KV Cache 命中率、系统吞吐瓶颈（木桶效应）拆解。
- 任何需要同时呈现「微观硬件单元阵列状态」与「宏观财务/性能倍率结论」的硬核数据镜。

## 参数表
| 参数 | 典型值 | 调节手感 |
|---|---|---|
| 矩阵规模 (`grid_cols × grid_rows`) | `8×4`（32 块）或 `6×4`（24 块） | `<12` 块没有集群规模感；`>64` 块单砖过小，状态色分不清 |
| 列染色波浪间隔 (`col_stagger`) | `0.08–0.12s` | `<0.05s` 像整屏同时闪；`>0.18s` 波浪太慢，拖沓 |
| 短板慢卡与快卡速度比 (`straggler_ratio`) | `1 : 3.2` | 差距 `<1:2` 观众感受不到「全员干等一张慢卡」的痛感 |
| 倍率数字字号 (`multiplier_font`) | `88–112px` (`JetBrains Mono`) | `<64px` 失去「账本暴击」张力；必须使用等宽字体防止滚动抖动 |
| 倍率砸落缩放 (`stamp_scale`) | `1.35 → 1.0` (`0.22s`, `power4.out`) | 配合 `thud` 同帧落定，严禁使用默认 `back.out(1.7)` 廉价弹跳 |

## HyperFrames 要点
- GPU 矩阵染色：若按列染色，可将每一列封装为一个独立平铺 clip（共 8 个列 clip），或用预染色的顶层列 clip 按 `stagger` 硬切覆盖底层灰块，避免创建 64 个碎 clip 导致轨道爆炸。
- 巨型金额与倍率滚动严格遵循 `counter-seek-safe`：用纯函数 `fmt(START + (END - START) * proxy.p)` 在 `onUpdate` 内根据 `document.getElementById` 赋值，保证任意帧 seek 数值精确。
- 左下角 PiP 圆形锚点保持稳定驻留，充当 `whip-x` 切章时的视觉载体（`carrier`）。

## 声音
- GPU 矩阵逐列染色波浪：每两列触发一次短促 `tick`（gain `0.24`）。
- 慢卡告警与最终 `6.7x / 25倍` 倍率砸落：同帧触发低沉有力的 `thud`（gain `0.55`）。
- 章节高速切出：配 `whoosh`（gain `0.38`，随 `whip-x` 从右向左 pan）。

## 何时不用
